# Chaos Jungle 0.1.0a2

This alpha release corrects output-token-limit injection for OpenAI-compatible
clients that send `max_completion_tokens`, including the LangGraph setup used
in our evaluation. CJ now rewrites that field without adding legacy limit
fields to the request. Requests using `max_tokens` remain supported.

CJ also distinguishes applying the limit from observing its effect: a
token-cap fault is marked as manifested only when a successful response reports
completion-token usage at or below the configured cap. Responses without usage
data remain unverified rather than being counted as confirmed exposure.

## Release files

| File | Purpose |
| --- | --- |
| `chaos_jungle-0.1.0a2-py3-none-any.whl` | Installable Python package |
| `chaos_jungle-0.1.0a2.tar.gz` | Python source distribution |
| `chaos-jungle-skills-v0.1.0a2.zip` | Fault-injection and resilience-evaluation skills |

Install the wheel in a Python 3.9+ virtual environment:

```sh
python -m pip install ./chaos_jungle-0.1.0a2-py3-none-any.whl
```

The skills ZIP contains the separate `chaos-jungle-injection/` and
`chaos-jungle-evaluation/` directories. Extract them into your assistant's
skills directory; they are not installed by `pip`.

This is a GitHub prerelease, not a PyPI publication. Infrastructure faults
can still require Linux tools and privileges on the selected target. Please
report bugs and use-case gaps in [GitHub Issues](https://github.com/pegasus-isi/Chaos-jungle/issues).
